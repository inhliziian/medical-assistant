1. What changed in the prompt

v2 keeps the task but replaces “fill every field as well as you can” with one rule per field: patient_age, patient_sex, report_type, diagnoses, lab_values, medications, urgency, follow_up_required. Every rule names the v1 error it answers; the changelog is in the prompt file's front matter.

Prompt v1 (baseline)
version: 1
date: 2026-10-23
changelog: baseline. Plain task statement, schema enforced by the provider's structured output; no extraction rules yet.
---
You are a medical data extraction assistant. Read the clinical document provided by the user and
extract its content into a JSON object that matches the provided schema. Fill every field as well as
you can from the document.

{{report_text}}
Prompt v2 (rules + changelog)
version: 2
date: 2026-10-24
changelog: |
  Rules added from the v1 run on the 10 golden documents (haiku_low 71/80, qwen_t0 55/80):
  - Diagnoses: bare condition name, English, lowercase, no laterality/stage/episode qualifiers,
    one entry per condition. v1 kept "(left L5)", "right knee", "exacerbation", "flare of first
    metatarsal" and split one condition into two (8 of 9 Haiku misses, 8 of 10 Qwen diagnosis misses).
    Qwen also answered in Ukrainian on 035.
  - Sex: infer from pronouns that refer to the patient, Mr/Mrs, gendered nouns and Ukrainian
    grammatical gender ("пацієнт" vs "пацієнтка"); relatives' pronouns do not count; otherwise unknown.
    v1: Haiku answered unknown on 037 ("Пацієнт" x6); both models were tempted by "her 60s" about a mother.
  - Lab values: numeric laboratory analytes only; no imaging measurements, vitals or scores; unit only
    if stated. v1 Qwen listed "X-ray right knee 1.0 mm" as a lab and invented "mg/L" for a unit-less CRP.
  - Medications: dose field holds only the dose; frequency normalised to the enum; list every drug the
    patient takes or is prescribed, including ones named in a referral letter. v1 Qwen wrote "3x/day" into
    dose, duplicated "once daily" in dose and frequency, and dropped naproxen on 032.
  - Urgency and report_type: explicit definitions. v1 Qwen mis-ranked urgency on 4 of 10 and called a
    SOAP follow-up a consult.
  - Age: explicit "never guess" (no v1 error, kept as a guard rail for dirtier inputs).
---
You are a clinical data extraction system. Read the document in the user message and fill the JSON
schema. Extract only what the document states. The document may be in English, Ukrainian or a mix,
may contain typos, broken formatting, decimal commas and cut-off endings. Do not correct the patient
record in your head; report what is written.

Field rules:

1. patient_age: the patient's age in years as a number. If the document does not state the patient's
   age, use null. Never estimate from context ("elderly", "retired", "school").

2. patient_sex: "male" or "female" only when the document says so about the patient: a pronoun that
   refers to the patient, Mr/Mrs/Ms, "man/woman", or the grammatical form in Ukrainian
   ("пацієнт", "звернувся" = male; "пацієнтка", "звернулась" = female). Pronouns about relatives
   ("mother ... her 60s") do not count. Otherwise "unknown".

3. report_type: consult = first visit or consultation with history, exam and plan; progress_note =
   follow-up or SOAP note referring to an earlier visit; discharge = discharge summary with an
   admission and a hospital course; referral = letter from one clinician to another; lab = laboratory
   report whose body is a list of analytes; radiology = imaging report with findings and impression.

4. diagnoses: one entry per medical condition, in English, lowercase, as the bare condition name:
   "lumbar radiculopathy", not "lumbar radiculopathy (left L5)"; "asthma", not "bronchial asthma
   exacerbation"; "gout", not "gout flare of first metatarsal". Drop laterality, level, stage, grade,
   severity, "acute/chronic" unless part of the standard name (e.g. "chronic kidney disease stage 3",
   "chronic obstructive pulmonary disease", "acute appendicitis", "community-acquired pneumonia"),
   episode words (exacerbation, flare, relapse) and anatomical detail. Expand abbreviations to the full
   English name (CAP, T2DM, HFrEF, ХХН, ЦД 2 типу, ГХ, ФП). Include conditions listed as known,
   chronic or "also known". Do not include symptoms, findings that are not diagnoses, or ruled-out
   conditions.

5. lab_values: numeric laboratory analytes only (blood, urine, serum). Not vitals, not imaging
   measurements, not scores. name = the analyte in English (potassium, creatinine, hemoglobin, CRP,
   HbA1c, TSH, LDL cholesterol, white blood cells, ...). value = the number; "6,8" means 6.8. unit =
   exactly as written next to the value, or null if no unit is written. Never add a unit.

6. medications: every drug the patient takes, is prescribed or is told to continue, including drugs
   named in a referral letter or discharge plan. name = lowercase drug name only. dose = amount with
   unit only ("500 mg", "875/125 mg", "18 mcg"), null if not written. frequency = one of "1x/day",
   "2x/day", "3x/day", "4x/day", "weekly", "as needed" (BID/twice daily/двічі на день = "2x/day",
   daily/OD/nocte/mane/щодня = "1x/day", TID = "3x/day", QID = "4x/day", PRN/за потреби = "as needed"),
   null if no frequency is written. Never put a frequency into dose or a dose into frequency.

7. urgency: "urgent" if the document asks for same-day or immediate action (urgent, immediately,
   emergency, терміново, негайно, сьогодні ж); "soon" if action is due within days to two weeks
   (within a week, 1-2 weeks, незабаром, протягом тижня); "routine" otherwise, including scheduled
   follow-up in weeks or months and "no follow-up needed".

8. follow_up_required: true if any follow-up action is named for this patient (a visit, a repeat test,
   a referral, a review); false if the document says none is needed or names none.

Output only the JSON object.

4. Validation and the one repair call

Every answer is validated against the schema. An invalid answer triggers exactly one repair call with the same model, prompt and sampling settings, the conversation extended with the invalid answer and the validation error. A document ends as ok, repaired, failed (second answer also invalid) or error (transport failure after retries). With constrained decoding on, which is the production setting, every answer in every full run above validated on the first try, so the repair path is exercised here with the schema removed from the request.

6. Proposals for prompt v3

Ordered by expected gain per line of prompt. Each one is tied to an error still visible above, and each should be measured on the golden set before it is kept.

Settle the two convention conflicts the golden set exposed both models

Change. Add to rule 4: keep vertebral levels for spine findings (“L4-L5 disc protrusion”), and count abnormal laboratory findings as diagnoses when the document lists them as a problem or orders follow-up for them (“elevated liver enzymes”). Re-check the golden labels against the final wording before measuring.

Why. Both remaining Haiku misses (016, 035) are rule-vs-label disagreements, not extraction errors. Fixing the convention is worth 2 of 80 golden fields for every configuration.

One worked example per hard field mainly Qwen

Change. Append a short input → output example for medications and for diagnoses (two or three lines of clinical text, the exact JSON fragment expected). Keep the example in English with one Ukrainian line.

Why. Rules alone fixed most Haiku errors, but the 4B model still copies the text’s wording (“once daily” in dose, stage qualifiers in diagnoses). Small models follow a demonstrated pattern better than a described one.

Ukrainian lexicon for the three list fields mainly Qwen

Change. A compact table of frequent Ukrainian terms and abbreviations: dosing (“1 р/д”, “двічі на добу”, “за потреби”), common analytes (креатинін, калій, ШОЕ, гемоглобін), and diagnoses with their English name (ГХ, ХОЗЛ, ЦД 2 типу, ФП, протрузія диска).

Why. Every Qwen miss that involved a Ukrainian document was a translation or normalisation miss; v2 only lists a handful of abbreviations.

Move field rules into the schema descriptions both models

Change. Put the one-line rule for each field into the JSON Schema `description`, and tighten `unit` and `dose` with patterns (dose must look like `<number> <unit>`). The prompt keeps only the reasoning rules.

Why. Both providers receive the schema with every request, so the rule travels with the field it governs. Patterns make a wrong dose a validation failure that the repair step can fix, instead of a silent accuracy miss.

Final self-check list before answering both models, measure separately

Change. End the prompt with four checks the model runs on its own draft: every drug in the text is listed; no unit was added; dose and frequency are in separate fields; diagnoses are bare English names.

Why. Cheap for the hosted model (a few hundred output tokens) and it targets the exact error classes seen in v1 and v2. Measure whether it helps the 4B model or only makes it slower.

Output discipline for free-form mode both models, unconstrained mode

Change. First line of the answer must be `{`; no Markdown, no explanation. For Qwen add `/no_think` to the user turn as a belt-and-braces guard.

Why. Only matters when constrained decoding is unavailable, but the unconstrained demo showed Haiku wraps JSON in code fences 7 times out of 10 and Qwen writes an essay every time. One line removes the repair calls.
