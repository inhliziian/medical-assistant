# Dataset: dirty clinical reports

50 synthetic clinical documents in the style of a doctor-appointment assistant's inputs, with
10 hand-verified golden labels. Built for checkpoint 1 of the course project (schema + prompt +
model comparison); the same files feed the RAG and agent stages later.

## Layout

| Path | What it is |
|---|---|
| `seeds/seeds.json` | 50 seeds: ground-truth facts (one `Report` each), generation hints, dirt plan, golden flag. Deterministic (`scripts/make_seeds.py`). |
| `clean/{id}.txt` | Documents as generated by the LLM from the seeds, before noise. Kept for reproducibility and error analysis. |
| `raw/{id}.txt` | **The dataset.** `clean` after the deterministic noise pass (`scripts/add_noise.py`). This is what the extraction pipeline reads. |
| `golden/{id}.json` | Golden labels for the 10 golden items, schema-valid (`schema/report_schema.py`). |
| `golden/STATUS.md` | Which golden items a human has verified against the raw text. |

## Spread (from the seeds)

- Report types: consult 12, progress_note 10, discharge 10, referral 6, lab 6, radiology 6.
- Languages: English 30, Ukrainian 10, mixed Ukrainian/English 10.
- Length: short 12 (45-90 words), medium 26 (120-220), long 12 (260-420).
- Missing data by design: age not stated in 19 documents, sex not inferable in 6, many medications
  without a dose or frequency, some lab values without a unit.
- Urgency: mostly routine, a minority `soon`, a few `urgent` (hyperkalemia, appendicitis, DVT).

## Kinds of dirt (`seeds[].dirt`)

| Key | Effect | Golden items |
|---|---|---|
| `typos` | 2-5 keyboard-style typos in ordinary words; never in numbers, drug names, lab names or diagnosis words | yes |
| `decimal_comma` | some `6.8` become `6,8` | yes |
| `mangle_headers` | mtsamples-style artefacts: `PLAN:, `, `plan:`, `ASSESSMENT: ,` | yes |
| `case_noise` | one line forced to UPPER or lower case | yes |
| `whitespace_noise` | lost blank lines, `word.Nextword`, dropped spaces after commas | yes |
| `drop_sentence` | one fact-free sentence removed | never |
| `truncate_tail` | last paragraph(s) cut like a dictation that stopped early, at least 65% of words kept, sometimes with `[...]` | never |

Golden items only receive noise that cannot change a labelled fact, so the seed facts remain the
correct answer after noising. Non-golden items may lose content; they are only used for validity,
latency and cost metrics, where that does not matter.

## How to regenerate

```bash
uv sync
uv run python -I scripts/make_seeds.py        # seeds (deterministic)
# generate data/clean/*.txt from the seeds with prompts/generation/v1.md (Claude Opus 5.5 agents)
uv run python -I scripts/verify_clean.py clean  # facts present, nulls silent, no PII
uv run python -I scripts/add_noise.py          # -> data/raw
uv run python -I scripts/verify_clean.py raw   # facts survived the noise
uv run python -I scripts/make_golden.py        # -> data/golden drafts + STATUS.md
```

## Golden-label protocol

1. The draft `golden/{id}.json` is the seed's facts, validated against the schema.
2. A human opens `raw/{id}.txt` and the draft side by side and checks every field against the text
   as it finally reads. The text wins: if the generator wrote something not in the seed, or the
   phrasing makes a different label correct, the JSON is edited.
3. The row in `golden/STATUS.md` is set to `verified: yes`.
4. Matching rules used by the scorer (fixed before any model output is inspected):
   enums and booleans exact; `patient_age` exact or both null; strings case-insensitive with
   punctuation and whitespace normalised; lists compared as sets ignoring order; `lab_values`
   matched on `name` + `value` (tolerance 0) + `unit`; `medications` matched on `name` + `dose` + `frequency`.

## Provenance and licence

All documents are synthetic, generated by Claude Opus 5.5 from the seeds in this folder. They
contain no personal data. A generation agent that uses the same model family as one of the
evaluated models introduces a mild familiarity bias; the deterministic noise pass and the planned
inclusion of real mtsamples notes mitigate it. Record this in the report's limitations section.
